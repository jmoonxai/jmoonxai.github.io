Multi-Robot Fire Response System

A multi-robot indoor fire response system connecting perception, navigation, decision-making, and robot control.

Role Technical PM / System Architecture & Integration
Focus System Design · Integration · Mission Flow

Overview

Spot, AMR, Vision, Navigation, and Manipulation modules were connected into a single mission flow to support indoor fire detection and initial response.

Rather than starting from isolated feature development, I first broke down the business requirements into robot-level functions and validated technical feasibility. Based on the verified functions, I designed the overall mission flow, system architecture, module responsibilities, and data flow.

Problem

The project involved multiple independent technologies, and completing each module individually did not guarantee success of the full fire response scenario.

  • Robot roles and responsibilities were not clearly separated.
  • Vision outputs had to be converted into data usable by navigation and control.
  • Different modules used different coordinate systems.
  • Multiple asynchronous robot states had to be managed as one mission.
  • Interface mismatches could lead to integration failure late in development.

I identified system integration — communication, coordinate systems, and state transitions — as the primary technical risk.

Key Integration Design

Interface Definition

Defined the input and output of each module before implementation, clarifying dependencies between Vision, Navigation, and Robot Control.

Coordinate System

Defined transformations between camera, robot, and map coordinates so spatial information could be shared consistently.

State Management

Managed asynchronous robot functions using mission states rather than relying only on sequential function calls.

Action

  • Decomposed the scenario into perception, navigation, control, and mission management functions.
  • Designed the end-to-end mission flow from fire detection to response action.
  • Defined responsibilities and data flow across Spot, AMR, Vision, and Navigation modules.
  • Specified communication interfaces, message formats, coordinate systems, and state transitions before implementation.
  • Managed development with integration readiness as a key criterion, not only individual feature completion.

Result

By defining the mission and system architecture before implementation, the project gained a clear functional scope and explicit module relationships.

Integration risks such as coordinate systems, communication methods, and state management were identified early and addressed through interface design.

Physical AI requires more than accurate individual AI models — perception, decision-making, navigation, and robot control must operate as one coherent system.

What I Learned

Define the system problem first

Complex robotics projects require clear functional decomposition before model or feature development begins.

Integration starts at architecture

Communication protocols, coordinate systems, and state transitions should be designed early rather than left until final integration.

Think beyond individual models

The core challenge of Physical AI is connecting perception, decision-making, and robot control into reliable real-world behavior.
