PROJECT TITLE

Multi-Robot Fire Response System

TECHNOLOGIES

AI × Robotics, Physical AI, ROS2, Isaac Sim

ROLE

Technical PM / System Architecture & Integration

PROJECT

실내 화재 상황에서 여러 로봇과 AI 모듈을 연결해 발화점 탐지부터 초기 대응까지 수행하는 다중 로봇 기반 화재 대응 시스템을 설계했습니다.

Spot, AMR, Vision, Navigation, Manipulation 등 서로 다른 기술 요소를 하나의 Mission Flow로 연결하고, 각 로봇과 AI 모듈의 역할, 데이터 흐름, 좌표계, 통신 인터페이스를 정의했습니다.

Problem

화재 대응 시나리오는 하나의 AI 모델이나 로봇 기능만으로 완성할 수 없었습니다.

Spot, AMR, Vision, Navigation, Manipulation 등 여러 기술 요소가 순차적으로 연결되어야 했으며, 각각의 기능이 개별적으로 정상 동작하더라도 모듈 간 인터페이스가 맞지 않으면 전체 Mission이 실패할 수 있는 구조였습니다.

  • 로봇별 역할과 수행 범위가 명확하지 않음
  • Vision 결과를 Navigation 및 Robot Control에서 활용 가능한 형태로 변환해야 함
  • 서로 다른 좌표계를 사용하는 모듈 간 위치 정보 정합이 필요함
  • 비동기적으로 동작하는 여러 기능의 상태를 하나의 Mission으로 관리해야 함
  • 통합 단계의 인터페이스 문제가 전체 일정에 영향을 줄 가능성이 높음

따라서 개별 기능 개발에 앞서 전체 시나리오 관점에서 시스템을 먼저 정의하는 과정이 필요하다고 판단했습니다.

Analyze

비즈니스 요구사항을 그대로 구현하기보다, 실제 로봇이 수행해야 하는 기능 단위로 요구사항을 분해했습니다.

  • 어떤 로봇이 이 기능을 수행하는가?
  • 필요한 Sensor / AI / Robot 기능은 무엇인가?
  • 입력과 출력 데이터는 무엇인가?
  • 다른 모듈과 어떤 방식으로 정보를 주고받는가?
  • 실제 환경에서 구현 가능한가?
  • 실패했을 경우 다음 상태는 어떻게 처리할 것인가?

분석 결과, 가장 큰 리스크는 개별 AI 모델의 성능보다 모듈 간 통신 방식, 좌표계, 상태 전이와 같은 Integration Interface의 불일치라고 판단했습니다.

이에 기능 구현보다 먼저 전체 Mission Flow와 System Architecture를 설계했습니다.

SYSTEM ARCHITECTURE

Perception

화재 및 주변 환경 정보를 인식하고 후속 모듈이 사용할 수 있는 형태의 정보를 생성합니다. Fire / Object Detection, Camera / Sensor Input, Position Estimation, Environment Information을 포함합니다.

Navigation

Perception 결과와 Mission 상태를 기반으로 로봇의 이동 목표를 결정하고 이동을 수행합니다. Localization, Path Planning, Goal Navigation, Obstacle Avoidance를 포함합니다.

Robot Control

Spot Mobility, AMR Movement, Manipulation / Action 등 각 로봇이 실제 환경에서 수행해야 하는 행동을 실행합니다.

Mission Control

Mission State Management, Robot Task Assignment, Module Communication, Failure / Exception Handling을 통해 여러 로봇과 모듈의 상태를 관리합니다.

Mission Flow

Fire Detection
↓
Fire Location Estimation
↓
Mission Generation
↓
Robot Task Assignment
↓
Autonomous Navigation
↓
Fire Scene Approach
↓
Fire Response Action
↓
Mission Status Update

각 단계의 입력과 출력 데이터를 정의하여 다음 모듈이 어떤 정보를 받아야 하는지 명확히 했습니다. 이를 통해 각 기능을 병렬로 개발하더라도 최종 Integration 단계에서 동일한 Interface를 기준으로 연결할 수 있도록 설계했습니다.

KEY INTEGRATION DESIGN

Interface Definition

각 기능의 입력과 출력을 사전에 정의하여 모듈 간 의존성을 명확히 했습니다. Vision 모듈이 단순 Detection 결과만 전달하는 것이 아니라, Navigation과 Robot Control에서 바로 활용할 수 있도록 객체 위치와 상태 정보를 구조화된 데이터 형태로 전달하도록 설계했습니다.

Coordinate System

Camera, Robot, Map 등 서로 다른 좌표계에서 생성된 데이터를 함께 사용할 수 있도록 각 좌표계를 정의하고 필요한 Transformation을 통해 공통 좌표계에서 위치 정보를 사용할 수 있도록 설계했습니다.

State Management

비동기적으로 동작하는 여러 기능을 단순 순차 호출로 관리하지 않고, Mission State를 기준으로 전체 흐름을 관리하도록 구성했습니다. 

IDLE
→ FIRE_DETECTED
→ TARGET_CONFIRMED
→ ROBOT_DISPATCHED
→ NAVIGATING
→ RESPONSE_READY
→ RESPONSE_EXECUTED
→ MISSION_COMPLETE

Action

요구사항 기능 분해

화재 대응 시나리오를 Perception, Navigation, Control, Mission Management 단위로 분해하고 각 기능의 기술적 구현 가능성을 검토했습니다.

Mission Flow 설계

발화점 탐지부터 로봇 이동과 초기 대응까지 전체 동작 순서를 정의하고 각 단계의 Dependency를 정리했습니다.

System Architecture 설계

Spot, AMR, Vision, Navigation 등 각 모듈의 역할을 정의하고 전체 시스템에서 데이터와 제어 명령이 어떻게 이동하는지 설계했습니다.

Interface 사전 정의

통신 방식, Message Format, Coordinate System, State Transition 등을 개발 전에 정의하여 Integration 단계에서 발생할 수 있는 충돌을 최소화했습니다.

Integration 중심 개발 관리

개별 기능의 완성 여부뿐 아니라 해당 기능이 다른 모듈과 실제로 연결될 수 있는지를 기준으로 개발 진행 상황을 확인했습니다.

Result

개발 시작 전에 전체 Mission과 System Architecture를 정의함으로써 각 팀원이 구현해야 할 기능의 범위와 모듈 간 연결 관계를 명확하게 만들 수 있었습니다.

또한 통합 단계에서 문제가 될 가능성이 높은 좌표계, 통신 방식, 상태 관리 등의 요소를 사전에 식별하고 Interface를 정의하여, 개별 기능 개발 이후 발생할 수 있는 Integration 리스크를 줄이는 방향으로 프로젝트를 진행했습니다.

이 프로젝트를 통해 AI 모델 자체의 성능뿐 아니라 Perception → Decision → Navigation → Robot Control이 하나의 시스템으로 연결되어야 Physical AI가 실제 환경에서 동작할 수 있다는 점을 경험했습니다.
